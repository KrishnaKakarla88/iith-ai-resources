One room in a bigger house

Context engineering: deciding everything that earns a seat in the window, on every call — system prompt, conversation history, retrieved content, memory, tool results, and space reserved for the reply. Prompt wording is still one lever. It's no longer the whole job.

Compare the same task two ways. A prompt-engineering-only approach writes one long, static instruction and sends it unchanged every time. A context-engineered approach sends a short instruction plus whatever's actually relevant right now — a fresh fact, trimmed history, not the whole transcript. The difference isn't better wording. It's a fresh decision, every call, about what data earns a seat.

For each candidate item, ask two questions: does it use the window now, and does it become future context — does it get resent on the next turn too? A tool result uses the window immediately, and often persists in history if left there unmanaged, which is exactly why compression and pruning exist.

Context curation should be driven by retrieval/eval quality, not "include everything that might be relevant" — over-inclusion has the same failure mode as context rot.

Is your context curated per call, or just accumulated?
